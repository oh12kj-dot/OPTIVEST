## 1. Outcome and deliberate scope

Build a small, stateless laboratory that evaluates **supplied synthetic holdings alternatives on supplied joint hypothetical paths**. It supplies the missing testable wealth-accounting kernel: self-financing initial trades, cash distributions, monthly wealth, cost exactly once, sampled drawdown/recovery, strict ruin and assumed expected-log arithmetic. A finite supplied probability-family lower envelope demonstrates the inner objective algebra. It does not estimate a return distribution, construct a plausible uncertainty set, optimize holdings, apply the Risk Budget, recommend an action or establish investment evidence.

This is a foundation beneath future forecast/risk/optimizer work, not completion of those components. It intentionally excludes material decision semantics that cannot yet be calibrated. Its UI must say `SYNTHETIC ACCOUNTING LAB — NOT AN INVESTMENT MODEL`. Synthetic input does not bypass a real-data gate: the lab has no route to a decision snapshot, authoritative security/evidence table, provider collector, editor impact field or recommendation endpoint.

Repository evidence: `service.seed` supplies ADR-0012's 7Y/USD/nominal/pre-tax/no-flow research mandate; `service.preflight` always denies eligibility and persists only blockers; `risk_editor.diagnostics` is a declaration checker, not a risk estimator; `app_for` and `verify_phase2` recognize the existing exact migrations; Phase 2 rows remain staged with permission gates. The accepted editor is engineering-only. No calibrated forecast, likelihood, objective ambiguity set, risk ambiguity set, stress calibration, residual margin or solver exists. README still contains historical under-review wording; a later implementation handoff should update that operational description without changing authority.

Selected boundary: USD only; nominal pre-tax; no external flows; reference starting wealth exactly USD 1,000,000; horizon 84 abstract monthly intervals (=7 years); fractional hypothetical units; a single initial rebalance followed by unchanged units, distributions paid to cash, terminal mark-to-market without forced liquidation. These are explicitly fixed synthetic mechanics under the research baseline, not a claim that the current edited mandate has these values. No current mandate/risk head is read or applied by the lab. If the editor changes to 10Y, the lab remains visibly the fixed 7Y example, not an impact calculation for that budget.

Non-goals: real ticker/issuer/holdings input, provider data imports, economic/statistical forecasting, FX, real wealth, investor taxes, corporate-action processing beyond the synthetic terminal-zero convention below, trade lots/settlement/partial fills, continuous rebalancing, historical backtest, optimization/ranking, risk feasibility, CVaR/chance/quantile/joint risk limits, permanent-loss model, sensitivity sizing, threshold calibration, personalized advice, persistence/activation/deployment. ## 2. Contract primitives and closed input

Every shape is closed at every depth; all listed keys are required. No coercion, defaulting, hidden padding, interpolation, auto-normalized probabilities or best-effort partial evaluation. Unknown keys and omitted keys are errors. IDs are ASCII `[A-Z][A-Z0-9_]{0,31}` with the required namespace prefix below. Text is trimmed nonempty Unicode, at most 512 characters, used only as inert display/provenance. A scalar count is a strict JSON integer excluding booleans.

`D` is a decimal string matching `(0|[1-9][0-9]{0,11})(\.[0-9]{1,6})?`. No signs, exponent, surrounding whitespace, JSON numeric values, NaN or Infinity. Remove fractional trailing zeroes and the trailing decimal point for canonical form; normalize zero to `"0"`. Never round input. Convert to exact rational numbers for ledger arithmetic. Input precision is an engineering convention, not six-digit forecast precision.

Required numeric input `V` is either D or exactly `{state, reason}`. `state` is one of `MISSING`, `UNKNOWN`, `STALE`, `CONFLICTING`, `UNAVAILABLE_PIT`, `NOT_APPLICABLE`; reason is nonempty text. Every V field below is applicable: `NOT_APPLICABLE` there is an invalid schema state; any other missingness state is retained in diagnostics and blocks the **entire** evaluation with `INPUT_INCOMPLETE`. These tags do not carry a numeric substitute. Malformed numerical syntax remains an invalid request even when another field is incomplete. All present numbers are explicitly hypothetical because the top-level origin is fixed. Missing timestamps/evidence must never be replaced by zero latency or a synthetic date.

The single public library entry is `evaluate_bytes(raw: bytes)`. HTTP and CLI pass the original bytes to it; dict/string/bytearray arguments are `TYPE_INVALID` at path `""`. There is no public mapping evaluator and no assertion that a reconstructed dict can preserve lost duplicate keys. Private typed helpers receive only a successfully decoded tree; expected-value oracles must not use them. Public library/CLI/HTTP parity covers the same raw input, except transport-only or CLI-file errors. Do not import/change the frozen risk-editor decoder to obtain different limits.

Wire decoding: strict UTF-8 JSON without BOM, duplicate object keys rejected at every depth, no non-standard constants or lone Unicode surrogate code points (including escaped lone surrogates). Raw input <=4,194,304 bytes, measured including whitespace before decode. Check stream size incrementally; do not trust Content-Length. Root depth is 0; each object value/array element has depth parent+1, including scalars and empty containers. Object keys do not add nodes or depth. Node count is 1 per scalar/container including root, recursively summing object values/array elements; maximum depth 16 and maximum nodes 100,000. Detect limits while parsing/constructing to avoid an unbounded tree; bounded lexical traversal may precede JSON tree creation. Parser-only tests can use non-Bundle roots; public evaluation still rejects their schema.

HTTP accepts exactly one Content-Type header with this complete grammar: `OWS "application/json" OWS [ ";" OWS "charset" OWS "=" OWS "utf-8" OWS ]`, where OWS is zero or more ASCII space/tab characters, brackets mean one optional group, and the quoted tokens compare case-insensitively. Quotes are grammar notation and are not accepted in the actual header. Additional parameters, duplicate headers and missing header fail CONTENT_TYPE. Content-Encoding is absent or exactly one header whose SP/HT-trimmed, case-insensitive value is `identity`; any other value, blank value, comma list or duplicate fails CONTENT_ENCODING. No decompression is performed. These two codes are 415.

Paths are RFC-6901 JSON Pointers: root `""`, zero-based decimal array indices, object keys escape `~` as `~0` and `/` as `~1`. Preserve wire array order for invalid/missing diagnostics; never expose an ID as a substitute index. A duplicate key reports the pointer to that member in the enclosing object at the first repeated occurrence in byte order. Malformed syntax/UTF-8/BOM/surrogate/nonstandard constant and size/depth/node failures report root `""` (codes `JSON_INVALID`, `JSON_ENCODING`, `JSON_SIZE`, `JSON_DEPTH`, `JSON_NODES` respectively). Decoder failure precedence is specified in section 6.1; do not claim a duplicate pointer from data whose syntax has not been validated.

## 3. Exact accounting and sampled path metrics

For asset i, initial ex-distribution price p_i0 and initial units q_i^old are common to all paths. For supplied alternative a, q_ai are fixed post-trade units, delta_ai=q_ai-q_i^old, and C_a is the exact sum of the six entry-cost components. Compute:

`cash_a0 = cash_old - sum_i(delta_ai * p_i0) - C_a`.

Require cash_a0 >=0 exactly and all units >=0. One hypothetical atomic self-financing net rebalance is the convention: sales fund purchases within this synthetic instant; no statement about real settlement or execution feasibility. Negative cash rejects the whole bundle as `UNFUNDED_ALTERNATIVE` with its ID. The lab does not silently drop a bad alternative and select among the rest. `W_a0_after = cash_a0 + sum_i(q_ai*p_i0) = W_initial - C_a`. Reject an arithmetic invariant failure; do not repair cash or clip costs. An alternative that spends all wealth on costs may have W=0; this is represented as ruin, not a small positive balance.

For joint path s, month k=1..84, provided cash factor g_sk, ex-distribution price p_sik and distribution d_sik:

`cash_ask = cash_as,k-1 * g_sk + sum_i(q_ai*d_sik)`

`position_value_asik = q_ai*p_sik`

`W_ask = cash_ask + sum_i(position_value_asik)`.

Cash accrues over the interval, distributions arrive at its end and first earn cash growth in the next interval. Units never change. Distributions are not also included in price returns, reinvested into units or paid externally. At month 84 value remaining assets at provided ex-distribution marks; do not charge imaginary exit cost or call it cash liquidation value. No separate cost penalty is deducted from logs, probabilities, comparison, drawdown or margin. Input path prices are after internal issuer/fund expenses; those expenses cannot be a second ledger charge. Initial costs appear at the initial event exactly once. Initial-price execution and later prices are synthetic marks, not tradable quotes.

An asset whose month-k price becomes zero is treated as terminally extinguished: a same-month distribution may represent its final cash settlement; all later prices and distributions must be exactly zero. It cannot resume trading/recover. Positive cash settlement is cash, not both cash and surviving equity value inferred by the engine. This terminal-zero rule is an accounting test convention, not a calibrated default/permanent-loss definition. Other corporate actions and recovery securities require a later design.

All funded paths have nonnegative wealth by construction. Once total wealth reaches zero it is absorbing under these rules; assert that property. W<0 is an accounting failure, never a forecast tail. W=0 is `RUIN` and remains zero, even if some unheld asset subsequently increases. Logs are computed only for strictly positive terminal wealth. A tiny positive wealth remains positive; no economic wealth floor or epsilon is used.

At each positive-wealth event, compute normalized fractions of cash and asset marked values; the **internal exact rational** sum=1, each >=0. Public fractions are separately rounded Numbers under section 4, so their displayed sum need not be exactly one; the exact invariant must be tested at the private rational-ledger seam as well as the public rounding bound. At W=0 all fractions are UNAVAILABLE Numbers with `ZERO_WEALTH_UNDEFINED`, not all-zero weights summing to zero. These are **descriptive fractions of supplied hypothetical holdings**, named `realized_hypothetical_fraction`; never `target_weight` or an optimizer recommendation. No rounding to real share lots occurs.

Path series includes initial pre-trade wealth (month 0, PRE_TRADE), initial after-cost wealth (month 0, POST_TRADE), and months 1–84. Drawdown includes the immediate cost:

`H_e=max_{j<=e} W_j`; `DD_e=1-W_e/H_e`; `sampled_max_drawdown=max_e DD_e`.

W_initial>0 guarantees H>0. This is grid-sampled drawdown including the initial cost event, not an estimate of the unobserved intramonth maximum. The same terminal wealth can coexist with different drawdowns. No default 25% or 35% threshold is applied.

Recovery state machine processes event indices 0=PRE_TRADE month 0, 1=POST_TRADE month 0, 2=MONTH month 1 through 85=MONTH month 84. Initialize H and anchor from PRE_TRADE, no open episode. For each subsequent event e: (a) if W_e>=H, close any open episode at e, then set H=W_e and anchor=e **even on an equal-high tie with no open episode**; (b) if W_e<H and no episode is open, open one using the current anchor; (c) if W_e<H with an episode already open, preserve its original anchor. A closing event cannot also open an episode. Exact rational comparison precedes every displayed rounding.

Episode shape is exactly `{peak_month,peak_event_kind,recovered_month,recovered_event_kind,observed_until_month,duration_months,right_censored}`. Event kinds are PRE_TRADE/POST_TRADE/MONTH; benchmark month 0 uses PRE_TRADE and its later events use MONTH. Duration=closing month minus peak month (possibly zero across two month-0 events); recovered episodes have both recovered fields present, observed_until_month=recovered_month and right_censored=false. At end, an open episode has both recovered fields=null, duration_months=null, observed_until_month=84 and right_censored=true; observed lower bound=84-peak_month. Return episodes in opening-event order. No episodes returns []. Event-kind fields disambiguate month-0 anchors without inventing elapsed time. Never convert right censoring into observed recovery. Section 8.1 freezes exact tie/cost examples.

### 3.1 Utility and probability arithmetic

For terminal W>0, `l_as = ln(W_as84/W_initial)/7`. Unit is annual natural-log wealth growth; neither arithmetic expected return nor expected CAGR. Path CAGR may be separately reported as `exp(l_as)-1`, labelled the path's annualized terminal growth. Expected path CAGR is not computed in V1; exponentiating expected log is labelled `geometric_equivalent_growth_under_assumption`, never expected CAGR.

For supplied distribution j, `L_aj = sum_s(p_js*l_as)`. If any p_js>0 has W_as84=0, L_aj=-infinity. A zero-mass ruin path is excluded before taking a log; never evaluate 0*(-infinity), which is undefined. Assumed ruin mass is exact `sum_s p_js * 1{W_as84=0}` and labelled `synthetic_zero_wealth_mass`, not bankruptcy/permanent-loss probability or a calibrated risk. Base has positive support on every ordinary path.

`lower_envelope_a = min_{j in objective_members} L_aj` is a **finite supplied-hypothesis diagnostic**, not validated U_objective or U*(A). Report every member utility and the display-tie IDs specified in section 4; never generate a preferred alternative/rank/action. There is exactly one comparison equation:

`difference_to_no_trade_a = (min_j L_aj) - (min_j L_NO_TRADE,j)`.

The two minima use the same supplied family but may have different minimizing member IDs. This is **difference of separately evaluated lower envelopes**, never `min_j(L_aj-L_NO_TRADE,j)`, base-utility difference or subtraction of displayed rounded strings. Compute each minimum and then their difference at active calculation precision before public rounding. If either minimum is -infinity, difference is `{kind:"UNAVAILABLE",value:null,reason:"NONFINITE_COMPARISON"}`, including NO_TRADE against itself when ruined. The UI label is exactly `Supplied lower envelope minus supplied NO_TRADE lower envelope (annual log units)`. For finite NO_TRADE against itself return FINITE zero. This is not the canonical decision hurdle: no best-feasible alternative search, optimized candidate exclusion, AddValue or RetentionValue exists.

Stress paths receive only pathwise accounting/drawdown/ruin diagnostics. No stress expectation, weighted ruin mass, inclusion in the lower envelope or binding PASS is computed. Comparator wealth is `W_initial * benchmark_level`, evaluated with the same timing/horizon and ordinary probability distributions; it has no investable fraction or trading recommendation.

## 4. Numerical method and computational boundaries

Use standard-library `fractions.Fraction` from canonical decimal strings for all cash, prices, units, costs, probability sums, wealth and comparisons. Signs, self-financing equality, zero/ruin classification, drawdown and recovery comparisons are exact. No float tolerance may admit borrowing, renormalize probabilities, repair fractions or suppress ruin. This avoids approving a numerical risk slack before such a decision is needed.

Transcendental display calculations use Decimal, not binary floating-point. Method ID `RATIONAL_LEDGER_DECIMAL_LOG_V1`: independently recompute the **entire** utility/exp/sum/min/difference calculation at decimal precision 80 and 120, ROUND_HALF_EVEN, with explicit local contexts (Emin=-999999, Emax=999999) and decimal traps for invalid/division-by-zero/overflow. Convert exact rational arguments at the active precision. Sum terms in canonical path-ID order. Select numerical minima from unrounded active-precision member utilities; no claim of exact transcendental ordering is made. For displayed membership, round each member and the selected minimum to the public representation and return all member IDs with equal representations, sorted by ID; differing mathematical values that display identically are intentionally all returned. If minimum=-infinity, include only -infinity members. Subtract unrounded numerical minima before public rounding. The two complete serialized numerical results must agree at 40 significant digits, including displayed-minimum membership; otherwise `NUMERICAL_NOT_VERIFIED` with no numerical result. This is a convergence check, not a mathematical error certificate, tie of exact utilities or decision margin. Cash/ruin checks remain exact. No solver, financial tolerance or positive wealth floor exists.

For every nonzero finite output x, first round to 40 significant decimal digits, then write sign `-` only when negative, one nonzero mantissa digit, a decimal point plus remaining mantissa digits only when needed after stripping trailing zeros, lowercase `e`, exponent `0` or unsigned positive integer or `-` followed by a positive integer (no plus sign/leading zero). Grammar: `-?[1-9](?:\.[0-9]{0,38}[1-9])?e(?:0|[1-9][0-9]*|-[1-9][0-9]*)`. Exact zero and rounded signed zero serialize only `"0"`. Examples: one=`"1e0"`, negative one=`"-1e0"`, 0.125=`"1.25e-1"`, 1,000,000=`"1e6"`, one third=`"3."` followed by 39 threes then `"e-1"`. Do not pad zeros to 40 digits. Decimal rounding does not change internal cash/probability comparisons. Input D and output derived-number grammars intentionally differ.

For exact rational x!=0 rendered at 40 digits, let a=floor(log10(abs(x))) determined by integer/rational comparison; require absolute display error <=0.5*10^(a-39). This is a public representation bound, not a risk/decision tolerance. For I assets plus cash, the rounded fraction sum differs from 1 by at most `(I+1)*5e-40`; do not renormalize the display to force equality. W14 checks this bound separately from exact internal sums. Probability validity is **always** exact on input D rationals: `0.333333+0.333333+0.333334` passes, three `0.333333` fail `PROBABILITY_SUM`; no display rule is used in that gate. Synthetic zero-wealth mass is summed exactly and only then rendered.

Outcome type `Number={kind,value,reason}` is closed: FINITE has derived decimal string and reason=null; NEGATIVE_INFINITY has value=null and reason=`ZERO_TERMINAL_WEALTH` for path log or `POSITIVE_ASSUMED_RUIN_MASS` for member/lower-envelope log; UNAVAILABLE has value=null and reason=`ZERO_WEALTH_UNDEFINED` for fractions or `NONFINITE_COMPARISON` for the comparison. No other Number reasons. Public JSON never contains NaN/Infinity numeric tokens. Monetary series has exact POSITIVE/ZERO state independently of display. A display/convergence failure yields an Evaluation failure, not another Number reason.

Bounds: 4 assets, 16 ordinary paths, 4 stress paths, 8 alternatives, 84 months, 4 objective distributions plus base; a maximum of 53,760 asset-month-alternative evaluations plus comparator work. Bound string lengths and all collections before rational arithmetic; use no random sampling, optimizer or combinatorial search. Evaluate with O(A*S*M*I) time and bounded materialized results. Canonical Evaluation <=32 MiB and full Artifact <=40 MiB, with exact measurement/error behavior in section 6.1. Requests above structural bounds fail rather than truncate. These are resource limits, not evidence sufficiency requirements. Record maximum-fixture elapsed time/peak memory on the actual review host; investigate >10 seconds or >256 MiB incremental peak for one evaluation. These are engineering review triggers only, never grounds to reduce path coverage silently. No concurrent workload/service-capacity claim is made.

### 6.1 Failure precedence, transport and size contract

All listed error codes form a closed registry. Generic unclassified exceptions map to INTERNAL_ERROR, never raw exception text. Root pointer is used for transport/file/authority/numerical errors. Semantic pointers use the original wire path of the offending value (cross-record checks name the affected object/array). No path, source bytes or stack is printed outside that JSON pointer.

Process stages are ordered; stop at the first failing stage, with these aggregation rules:

1. Lab CLI argument grammar (before file/context access): misuse ARGUMENT_INVALID, status INVALID_INPUT, root finding, provenance=null, input_sha256=null. HTTP routing/method handling outside the lab is unchanged; media checking below applies to its POST. `wealth-lab --help` is the sole explicit human-text exception, exit 0, no evaluation.
2. Authority/runtime context: fixed Policy hash then fixed frozen design hash, then manifest/runtime collection and loaded-source consistency. Failure emits one code `POLICY_MISMATCH`, `DESIGN_MISMATCH`, `SOURCE_UNAVAILABLE`, `SOURCE_CHANGED`, or `RUNTIME_UNAVAILABLE` in that priority order; ties within a class collapse to root. Evaluation status INTERNAL_ERROR, provenance=null, input_sha256=null. Missing/unreadable Policy/design are SOURCE_UNAVAILABLE; a readable wrong hash uses the corresponding mismatch code. A draft is never a freeze. The actual implementation's frozen constants are set only by a later ADR.
3. Transport/acquisition: HTTP Content-Type before Content-Encoding, then bounded byte read. CLI path errors `INPUT_FILE_MISSING`, `INPUT_FILE_NOT_REGULAR`, `INPUT_FILE_UNREADABLE`, then byte bound JSON_SIZE. Reject symlink/reparse input files as NOT_REGULAR; never echo the path. Public library non-bytes gives TYPE_INVALID. These failures have verified provenance, input_sha256=null. Authority fails first even if the request would also be malformed.
4. Decode: bytes-size -> UTF-8/BOM/surrogate -> lexical nesting/node bound -> complete JSON syntax/constants -> duplicate members. A malformed document cannot acquire a duplicate-key pointer; duplicates are checked on a syntactically valid ordered-pairs tree. Structural-bound failures use JSON_DEPTH before JSON_NODES if both occur; perform a bounded lexical check without constructing an over-limit tree. JSON nodes must use section 2's semantic counting (not punctuation tokens). Decoder returns one root finding except first byte-order duplicate, status INVALID_INPUT, hash=null, verified provenance. A parser-only decoder seam may expose these guarantees without requiring a Bundle.
5. Typed schema: visit object keys in Unicode scalar order and arrays in wire order. Aggregate all independent schema/domain findings, but do not descend into a field with invalid container/type, or into an unknown key. Required key path is the missing member. Codes UNKNOWN_FIELD / REQUIRED_FIELD / TYPE_INVALID / VALUE_RANGE / SET_MEMBERSHIP / FIELD_NOT_APPLICABLE. Duplicate IDs, wrong array count or missing membership use SET_MEMBERSHIP at the containing array. D lexical mismatch uses TYPE_INVALID; valid D outside its domain uses VALUE_RANGE. Wrong literal string uses VALUE_RANGE. Blank/too-long text uses VALUE_RANGE. Full typed-invalid set wins over missing V tags; do not emit missing tags in this outcome. Hash=null, status INVALID_INPUT, verified provenance.
6. Valid typed shape with missing V: normalize shape/text/D and hash the canonical incomplete input, emit all missing V states with their original pointers, status INPUT_INCOMPLETE. Do not evaluate any economic/cross-record equality or funding invariant. Thus MISSING plus a would-be unfunded trade is only INPUT_INCOMPLETE; malformed D plus MISSING is stage-5 INVALID_INPUT. Present-only set-membership rules remain stage 5.
7. Fully present cross-record/accounting input: canonical input hash exists. Aggregate independently applicable checks: INITIAL_WEALTH_MISMATCH at `/initial_state`, PROBABILITY_SUM at each masses array, NO_TRADE_MISMATCH at its positions array, COST_WITHOUT_TRADE at entry_costs, TERMINAL_ZERO_REVERSAL at each offending price/distribution/benchmark level. If initial wealth is invalid, skip funding checks that depend on it; otherwise UNFUNDED_ALTERNATIVE at each alternative object. No path calculation until these pass. Status INVALID_INPUT with verified provenance.
8. Exact ledger invariant assertion: any failure `ACCOUNTING_INVARIANT`, status INTERNAL_ERROR, valid input hash/provenance, result=null. This is a programmer/runtime defect, not repairable bad input. Then Decimal evaluation: trapped arithmetic or nonconvergence `NUMERICAL_NOT_VERIFIED`, status NUMERICAL_NOT_VERIFIED, valid hash/provenance, result=null. Unexpected exception INTERNAL_ERROR with any successfully established input hash/provenance. No detail leakage.
9. Before emitting success, recheck Policy/design and source manifest against the invocation context. Changed/mismatched authority returns its stage-2 failure (both provenance and input hash null), not stale provenance. Then canonical size checks below; failure RESULT_SIZE or ARTIFACT_SIZE, status NUMERICAL_NOT_VERIFIED with valid hash/provenance, result=null. No bytes of a partial success are emitted.

All failures use full Evaluation with the fixed boundary object. HTTP codes: CONTENT_TYPE/CONTENT_ENCODING 415; JSON_SIZE 413; stage 4–7 errors otherwise 422; stage 2/8/9 and INTERNAL_ERROR 503. CLI exits: argument/input/decoder/typed/incomplete/accounting-input rejection 2; authority/runtime/computation/size failure 1; success 0. For example and capabilities, source/runtime failures use Evaluation too. The same root INVALID_INPUT JSON code ARGUMENT_INVALID is printed for CLI misuse; do not let argparse print source paths or partial usage to stdout. Help is deliberate and separate.

Stdout is exactly one complete canonical JSON value followed by LF for normal CLI outcomes. If output writing fails/broken pipe, it cannot promise deliverable JSON on that channel: exit 1, do not append a second JSON object to partial stdout, and attempt only `OUTPUT_WRITE_FAILED\n` on stderr; if stderr is also unavailable, exit without further text. This is a delivery failure, not an Evaluation pretending the write succeeded. HTTP response disconnection likewise cannot promise a received error body; no database/write retry follows.

Canonical bytes C(x) are section 7's exact serialization. After successful Evaluation E, require `len(C(E)) <= 33,554,432` (32 MiB). Then construct Artifact A including its final digest; require `len(C(A)) <= 41,943,040` (40 MiB). Bounds include every provenance/key/quote/UTF-8 byte, exclude CLI's single LF and HTTP headers. Equality passes. Measure serialized bytes, not string length, memory size, compressed length or result subtree. Check Evaluation first, Artifact second; refuse before response/download. The small failure Evaluation is not replaced recursively for exceeding a test-injected success-size boundary. A browser Blob is the returned canonical Artifact bytes, no display whitespace. Bounds do not change numerical or financial semantics.
